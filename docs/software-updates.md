# 기존 구성 자동 업데이트와 검증

2026-10-25 사용자가 전체 설치 스킬·구성의 최신화와 자동 업데이트를 요청했다.
기존 `trace` 한 개와 실제 일정은 유지한다. 새 컴퓨터는 이 호스트의 승인이나
인증을 상속하지 않는다. 호스트·자동화 ID가 일치하는 비공개
`maintenance_authorization.software_updates`만 적용 권한을 제공한다.

## 소유자별 절차

| 구성 | 최신화 경로 | 검증 |
|---|---|---|
| TRACE 개인 지침·스킬 | 공식 변경/정확한 upstream 릴리스 검토 후 manifest 설치 | 원본·설치본 해시, 호출 정책, 관련 로딩/동작 |
| Ponytail | 안정 태그·커밋·SKILL.md를 함께 고정 | 수정된 사용자 파일 보존, 명시 호출·작업 범위 유지 |
| RTK | 검토한 OSS 플랫폼 자산과 소유 설치 도구 | digest·버전·종료 코드·증거·격리 기록 범위 |
| 기존 원격 플러그인 | 지원 CLI `plugin add 기존ID --json` | 소유자 응답·설치 manifest·후속 native 목록·활성 상태 |
| 앱 bundled/system·primary runtime | 앱/런타임 소유자의 제공 원본 | 현재 앱 업데이트 상태, 제공 원본과 활성 설치 버전 |

캐시 폴더를 직접 편집하거나 새 플러그인을 일괄 설치하지 않는다. 앱 소유 CLI를
독립 CLI로 덮어쓰지 않는다. `plugin marketplace upgrade`는 Git marketplace
갱신이며 원격 curated 또는 앱 런타임 업데이트를 대신하지 않는다. 개발 중인
app-server 플러그인 설치 API를 운영 자동화에 사용하지 않는다.

## 기존 루틴 안에서 실행

```text
python -B scripts/software_updates.py refresh-plugins
```

현재 설치·활성화된 승인 ID만 대상으로 한다. 새 ID는 자동 등록하지 않는다.
플러그인별 성공한 소유자 확인이 24시간 이내이고 설치 identity가 같으면 재사용한다.
앱/런타임의 로컬 원본이 같으면 재설치하지 않는다. 비활성화 패키지는 유지한다.
정기 작업 외에는 앱/런타임 변경·관련 오류·명시 요청 때만 재확인한다.

단순 조회는 `software_updates.py collect`다. 설치된 패키지와 그 SKILL.md, 개인·시스템
스킬만 제한된 범위에서 지문을 수집한다. 미설치 전체 카탈로그나 드라이브를 검색하지
않는다. auth/session/고객 파일은 읽지 않는다. 결과는 기존 `routine-review.json`의
`software_updates`에 한 벌만 유지한다. 모르는 버전·실패한 경로는 정상으로 만들지 않는다.
다른 설치 위치에는 기존 설치 도구와 같은 `--home`, `--state`, `--personal-skills`를
사용한다. CLI 검색이 불가능하면 검증한 실행 파일을 `--codex`로 지정할 수 있다.
공통 정책에 드라이브 문자나 사용자 이름을 고정하지 않는다.

공식 원문 변경이 실제 정책에 필요한지 검토한다. TRACE 관리 파일은 plan/apply/verify,
직전 복구점, 영향 범위 검사와 반복 적용으로 마감한다. 플러그인은 소유자의 지원 절차를
사용하고 임의 캐시 복원기를 만들지 않는다. 실패나 권한/인증 정책 변경은 중단·기록하고
변하지 않은 실패를 다시 실행하지 않는다. 신규 외부 연결·권한·hook·의존성 또는 불명확한
주요 마이그레이션은 검토 대상으로 남긴다. 기존 Claude, 프로젝트, 모델·추론 강도는 보존한다.
GitHub 게시 권한은 이 자동 업데이트 승인과 별개다.

## Codex 전용 관측

대시보드는 허용한 요약만 읽는다: 설치 패키지/스킬 수와 버전, 검증·업데이트 시각,
미확인 항목, 실제 저장 일정, 승인된 MCP 점검 결과. 사용 한도 도구가 제공되면 기존
루틴에서 계정 Codex 한도를 한 번 확인하고 사용률·기간·리셋 시각만 보존한다.
계정 ID·잔액·원문 응답은 저장하지 않는다. 제공되지 않으면 미수집으로 표시한다.
계정 공유 한도는 이 대화의 토큰 사용량이나 RTK 절감률이 아니다.

정적 검사, 새 세션 로딩, 실제 도구 실행과 UI 렌더링을 구분한다. 설치 완료를 모델의
정확한 행동이나 미래 예약 실행의 증거로 해석하지 않는다. 앱/호스트가 꺼져 있으면
실행하지 못하며, 알려진 실패만 기록한다. 변경 없는 결과로 매일 알림을 보내지 않는다.
