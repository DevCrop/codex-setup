# 글로벌 Codex 위임 흐름

실행 정책의 정본은 [글로벌 지침](../global/AGENTS.md)과 조건부
[위임 가이드](../global/guides/agent-orchestration.md)다. 이 문서는 사용 예시다.
기존 Claude 설정과 프로젝트 파일은 수정하지 않는다.

```text
요청과 프로젝트 규칙 확인
  → 작은 작업·강한 결합: 부모가 직접 처리
  → 독립 작업·실질적 이점: 필요한 자식만 위임
  → 부모가 결과 통합·영향 범위 검증
  → 통과: 완료 / 실패: 원인 확인 → 필요하면 한 번 보정 위임
  → 동일 실패 지속: 부모가 인수하거나 실제 차단 사유 보고
```

| 작업 예시 | 기본 판단 |
|---|---|
| SCSS 한 컴포넌트 수정, TS 함수 오류 | 직접 처리 |
| 많은 모듈에서 호출 경로 찾기 | 요약이 도움이 되면 explorer 한 개 |
| 인터페이스가 확정된 독립적인 프런트·백엔드 수정 | 소유 파일을 나눠 필요한 경우 병렬 처리 |
| 같은 파일·공유 타입·API 계약을 동시에 변경 | 계약 확정 후 순차 처리 |
| 완료된 작은 변경에 상시 리뷰 에이전트 추가 | 자동 추가하지 않음 |

부모 모델과 추론 강도는 사용자가 고른 값을 유지한다. 기존 설정은 동시 자식
최대 2개, 일반 자식 Sol medium, explorer Sol high다. 두 개를 항상 쓰라는 뜻은
아니며 공식 최적값이나 측정된 속도 향상으로 설명하지 않는다. 자식의 재위임과
반복 보정은 가이드의 제한을 따른다. 이 제한은 지침이며 별도 강제 실행기가 아니다.

## 프로젝트에서 사용

같은 Codex 홈을 사용하는 새 로컬 세션은 글로벌 지침과 해당 프로젝트의 지침을
함께 읽는다. 프로젝트마다 글로벌 파일을 복사하거나 별도 오케스트레이터를 설치할
필요는 없다. 프로젝트에는 기존 규칙 문서, 명령, 완료 조건만 관리한다.
프로젝트 override, 자체 agent 설정, 다른 CODEX_HOME 또는 호스트의 상위 제한이
있으면 효과가 달라질 수 있다. 필요할 때 그 차이만 확인한다.

일반적으로 작업 결과와 완료 조건을 요청하면 된다. 병렬화를 명확히 지정하려면:

```text
이 프로젝트의 AGENTS.md와 관련 규칙에 맞춰 수정해줘.
호출 경로 조사와 실제 수정이 독립적이면 필요한 부분만 위임해줘.
같은 파일을 동시에 수정하지 말고, 통합 후 관련 검증이 통과하면 마무리해줘.
```

파일 일치와 CLI의 지침 렌더링은 설치·로딩의 증거다. 실제 에이전트 실행의 정확성,
항상 자동 위임되는 동작, 속도·토큰 절감까지 보장하는 증거는 아니다. 원본 대화나
비밀을 수집해 검증하지 않는다. 모델 벤치와 API 기반 실행은 추가하지 않는다.

[공식 Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)는
독립적인 탐색·분석과 요약의 이점을 설명하며 병렬 쓰기 충돌 및 추가 토큰 비용을
명시한다. [공식 AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)는
글로벌·프로젝트 지침의 로딩과 override 우선순위를 설명한다. 검토일: 2026-10-25.
